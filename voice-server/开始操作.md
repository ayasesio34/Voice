# 部署手册：从一台空服务器到跑起来

**这份文档记录的流程全部在真机上验证过。** 照着从头做一遍，大约 20 分钟。

> 日常运维命令、故障排查、配置项解释都在 [README.md](README.md)。
> 本文只讲**从零部署**。

---

## 开始之前

| 项目 | 要求 |
|---|---|
| 服务器 | 阿里云 ECS，2 核 2 GiB 起，**大陆地域**，Ubuntu |
| 带宽 | 100 Mbps 峰值 + 按使用流量计费（最省钱） |
| 域名 / 备案 / 证书 | ❌ **全都不需要** |
| Docker | ❌ **不需要**（国内拉 Docker Hub 镜像经常失败，我们直接用官方二进制） |
| 你电脑上的工具 | `ssh`、`scp`（Windows 10+ 自带）、Python 或 Node（用来起本地测试页） |

**为什么不用 Docker**：国内从 Docker Hub 拉镜像会频繁 `unexpected EOF` / `unknown error`，配镜像源也治不好（阿里云加速器只加速"官方镜像"，`livekit/livekit-server` 不在其列）。而 LiveKit 官方提供的**单个可执行文件只有 18 MB**，直接下载解压就能跑，效果完全一样。

---

## 第 1 步 · 连上服务器

打开 PowerShell（`Win` → 输入 `powershell` → 回车），粘贴：

```powershell
ssh root@你的公网IP
```

两次提问这样答：

| 问什么 | 答什么 |
|---|---|
| `Are you sure you want to continue connecting?` | `yes` |
| `password:` | 你的服务器密码（**屏幕不显示字符，正常**） |

✅ 提示符变成 `root@iZxxxxxxxx:~#` 就进去了。

> 💡 用阿里云网页版「远程连接」也行，效果一样。但第 4 步传文件必须在你自己的电脑上做。

---

## 第 2 步 · 装 LiveKit（18 MB）

粘贴这一整行。它会依次试 3 个下载源，哪个通用哪个：

```bash
cd /opt && for u in "https://ghfast.top/https://github.com/livekit/livekit/releases/download/v1.13.8/livekit_1.13.8_linux_amd64.tar.gz" "https://gh-proxy.com/https://github.com/livekit/livekit/releases/download/v1.13.8/livekit_1.13.8_linux_amd64.tar.gz" "https://github.com/livekit/livekit/releases/download/v1.13.8/livekit_1.13.8_linux_amd64.tar.gz"; do echo ">>> 尝试: ${u:0:35}..."; curl -fL --connect-timeout 10 --max-time 240 -o livekit.tar.gz "$u" && break; done; ls -lh /opt/livekit.tar.gz
```

✅ 看到 `19M` 左右就成功了。

**校验 + 安装**（两行分开粘）：

```bash
cd /opt && sha256sum livekit.tar.gz
```

期望值（必须一模一样）：

```
059f6de65da11a57400e4646027da705d592ce42acb48c08570a397df446f869  livekit.tar.gz
```

```bash
cd /opt && tar xzf livekit.tar.gz && install -m 755 /opt/livekit-server /usr/local/bin/livekit-server && livekit-server --version
```

✅ 输出 `livekit-server version 1.13.8`

> 📌 想装更新版本：去 <https://github.com/livekit/livekit/releases> 看最新 tag，把上面三处的 `v1.13.8` 和 `1.13.8` 一起换掉。

---

## 第 3 步 · 装 Node（32 MB）

**为什么用官方二进制而不是 `apt install nodejs`**：Ubuntu 源里的 Node 版本偏旧（Fastify 5 要求 ≥ 20），而且我们依赖的 `node:sqlite` 需要 Node ≥ 22.5。

粘贴这一整行（走 npmmirror，国内很快）：

```bash
cd /opt && curl -fL -o node.tar.xz https://cdn.npmmirror.com/binaries/node/v24.21.0/node-v24.21.0-linux-x64.tar.xz && tar xf node.tar.xz && cp -a node-v24.21.0-linux-x64/. /usr/local/ && node -v && npm -v
```

✅ 输出：

```
v24.21.0
11.x.x
```

---

## 第 4 步 · 上传项目

### ⚠️⚠️ 千万不要直接 `scp -r` 整个文件夹 ✗

`backend/node_modules` 里有 **3100+ 个文件、约 17 MB** ✓
`scp -r` 是**一个文件一个文件**传的 ✗ 在 SSH 上慢得像卡死，而且
**传上去的依赖完全没用** —— 服务器上第 9 步会自己跑 `npm install` ✓
（真踩过：盯着进度条等十几分钟，以为传完了，其实才一半 ✓）

### ✅ 正确做法：先打包成一个文件

**在你自己的电脑上**（新开一个 PowerShell 窗口，连服务器的那个别关）：

```powershell
cd "路径\voice-server"
.\pack.ps1
```

把 `路径` 换成本地 `voice-server` 文件夹所在目录。

✅ 输出 `大小: 0.15 MB` + `node_modules 零残留`（**0.15 MB，不是 17 MB** ✓）

然后上传这**一个文件**（几秒钟）：

```powershell
scp ..\voice-server.tgz root@你的公网IP:/opt/
```

> 📌 注意那个 `..\` ✗ —— 产物被放在**上一层**目录 ✓
> 因为它不能把自己打进自己里面 ✓（脚本打印的命令里也写了 ✓）
> 嫌麻烦就用脚本打印的**绝对路径**那一条 ✓

**回到服务器窗口**，解开：

```bash
cd /opt && rm -rf voice-server && tar xzf voice-server.tgz && ls /opt/voice-server && rm -f /opt/voice-server.tgz
```

✅ 应该看到 `README.md`、`backend`、`livekit`、`scripts`、`tools` 等。

> 📌 `rm -rf voice-server` 是为了清掉之前用 `scp -r` 传了一半的残骸 ✓
> 第一次传的话它不存在，也不报错 ✓
>
> 📌 为什么用 `tar.gz` 而不是 Windows 的 `Compress-Archive`（zip）✗
> Linux 上 `unzip` 不一定装了 ✓ 而 `tar` 一定在 ✓ 少一次"命令不存在"的来回 ✓

## 第 5 步 · 初始化

粘贴这一整行：

```bash
cd /opt/voice-server && sed -i 's/\r$//' scripts/*.sh && chmod +x scripts/*.sh && ./scripts/init.sh
```

它会做四件事：

1. 从阿里云元数据服务探测公网 IP，写进 `livekit/livekit.yaml` 的 `node_ip`
2. 生成随机的 `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` / `INVITE_CODE`，**同时**写入 `.env` 和 `livekit.yaml`
3. 加 2 GiB swap（阿里云 Ubuntu 镜像默认没有，2 GiB 机器上这是防 OOM 的保险）
4. 调内核 UDP socket 缓冲区（高码率媒体必需）

✅ 最后会打印一个方框：

```
  API Key     : LK3f9a2b...
  邀请码      : a1b2c3d4e5f6        ← ★ 抄下来，客户端要用
  信令地址    : ws://你的IP:7880
  node_ip     : 你的IP
```

---

## 第 6 步 · 装成 systemd 服务

**这一步不做的话，服务器一重启服务就全没了。**

```bash
cd /opt/voice-server && ./scripts/install-services.sh
```

✅ 两个服务都应该是 `active (running)` + `enabled`。

---

## 第 7 步 · 开安全组（必须用鼠标在网页上做）

浏览器打开 <https://ecs.console.aliyun.com>：

1. 左侧「实例和镜像」→「实例」→ 找到你那台 → **点实例 ID**
2. 上方标签「**安全组**」→ 点安全组 ID → 「**配置规则**」
3. 「**入方向**」→「**手动添加**」
4. 加下面 4 条，每条填完点「保存」

| 端口范围 | 协议类型 | 授权对象 | 用途 |
|---|---|---|---|
| `7880/7880` | 自定义 TCP | `0.0.0.0/0` | LiveKit 信令 |
| `7881/7881` | 自定义 TCP | `0.0.0.0/0` | UDP 不通时兜底 |
| `7882/7885` | **自定义 UDP** | `0.0.0.0/0` | ★ **媒体流。漏了会退回 TCP，或直接没声音** |
| `3005/3005` | 自定义 TCP | `0.0.0.0/0` | 后端 API |

> ⚠️ 最容易犯的错：把 `7882/7885` 也选成了 **TCP**。必须是 **UDP**。

---

## 第 8 步 · 验收

```bash
cd /opt/voice-server && ./scripts/selfcheck.sh
```

✅ 最后一行 `结果：XX 通过  0 失败`。

⚠️ **只要不是 0 失败，先别往下走**，按输出的提示排查。

**客户端侧验收**（在你自己电脑上）：

```powershell
cd "路径\voice-server\tools\test-page"
python -m http.server 8123 --bind 127.0.0.1
```

浏览器打开 **`http://127.0.0.1:8123`**（必须是 `localhost` 或 `127.0.0.1`，不能用 `file://`），填邀请码，点连接。

> **为什么必须从 localhost 打开**：浏览器的 `getUserMedia` / `getDisplayMedia` 要求页面处于安全上下文。`http://localhost` 本身就是安全上下文，而 HTTP 页面连 `ws://` 不算混合内容 —— 所以**不需要域名、不需要证书**就能测。
>
> 如果 8080 端口被你机器上别的程序占了（比如某个 Express 应用），换个端口即可。

## 全流程速查

```bash
# 1. 连服务器
ssh root@你的IP

# 2. LiveKit
cd /opt && curl -fL -o livekit.tar.gz "https://ghfast.top/https://github.com/livekit/livekit/releases/download/v1.13.8/livekit_1.13.8_linux_amd64.tar.gz" \
  && tar xzf livekit.tar.gz && install -m 755 livekit-server /usr/local/bin/

# 3. Node
cd /opt && curl -fL -o node.tar.xz https://cdn.npmmirror.com/binaries/node/v24.21.0/node-v24.21.0-linux-x64.tar.xz \
  && tar xf node.tar.xz && cp -a node-v24.21.0-linux-x64/. /usr/local/

# 4. 上传（在你自己电脑上）
#    scp -r voice-server root@你的IP:/opt/

# 5. 初始化
cd /opt/voice-server && sed -i 's/\r$//' scripts/*.sh && chmod +x scripts/*.sh && ./scripts/init.sh

# 6. 装服务
./scripts/install-services.sh

# 7. 开安全组（网页操作，见上）

# 8. 体检
./scripts/selfcheck.sh

# 9. 装后端依赖（第一次必需）
cd /opt/voice-server/backend && npm config set registry https://registry.npmmirror.com && npm install --omit=dev
systemctl restart voice-backend
```

> ⚠️ 第 9 步容易漏：`install-services.sh` 只写服务定义，**后端依赖要先 `npm install`**，否则 `voice-backend` 会一直重启。顺序上放在第 6 步之后、第 8 步之前也行。

## 常见坑（都是实际踩过的）

| 现象 | 原因 | 处理 |
|---|---|---|
| `unexpected EOF` / `unknown error` 拉镜像 | Docker Hub 在国内被限速 | **本项目不用 Docker**，别去折腾镜像源了 |
| `EADDRINUSE: 0.0.0.0:3000` | 3000/3001 被别的程序占了（比如 Haven） | 我们的后端用 **3005**，见 `.env` 的 `PORT` |
| `Cannot GET /`，且响应头有 `X-Powered-By: Express` | 你访问的端口上是别的 Express 应用 | 换端口，并用 `127.0.0.1` 而不是 `localhost` |
| `bad interpreter: /bin/bash^M` | 脚本被 Windows 换行符污染 | `sed -i 's/\r$//' scripts/*.sh` |
| 屏幕共享统计里码率一直是 0 | **房间里只有你一个人，没人订阅** | 正常。LiveKit 的 `dynacast` 不给无人观看的流浪费带宽。开第二个窗口进同一房间就能看到码率起来 |
| 画面"看起来清晰"但码率很低 | 你看到的是**本地采集预览**，不是真正发出去的流 | 用第二个窗口当观众才能判断真实质量 |
| 连接走 TCP 而不是 UDP | 安全组 UDP 规则没生效（多半选成了 TCP） | 改安全组，然后 `selfcheck.sh` 会读日志告诉你最近一次用的哪种 |
| Node 命令找不到 | 装完没在 PATH 里 | `cp -a` 到 `/usr/local/` 后重开一个 shell |
